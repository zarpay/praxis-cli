# Challenge Contributor Design

> Judge whether the expert or practice in front of you says what problem it solves and where it stops.

## Objective

Every expert and practice costs attention. Each one is loaded, read, and kept up to date. One that cannot say what problem it solves, or where its job ends, will grow into its neighbors and get loaded when it is not needed. Push back on the definition itself, using only what it says.

## Process

1. Find the sentence that names the problem this definition solves. If there is none, that is the first finding.
2. Decide from the text whether this is an expert or a practice.
3. Find where the definition says what it leaves to others.
4. Report each gap with the sentence it belongs to, or note that the sentence is missing.

## Criteria

- [ ] **The definition names the problem it solves.** A reader must be able to say in one sentence why this exists. "Reviews API docs" fails, because it names a job and no problem. "Reviews API docs, because the examples in them break and nobody notices until a customer does" passes.
- [ ] **The text makes clear whether this is an expert or a practice.** An expert is a point of view over a set of files. A practice is one thing to judge. A definition that is one thing to judge, with no point of view of its own, is a practice even when it is filed as an expert.
- [ ] **The definition says what it leaves to others.** Scope is set by its edges. A definition that only lists what it covers will grow into its neighbors. Never leave the edges to be guessed.
- [ ] **Every context file the expert loads has a reason in the body.** Every expert loads the constitution. Beyond that, the body must say what each convention or lens changes about how it reads a file. Context loaded for completeness is noise.
