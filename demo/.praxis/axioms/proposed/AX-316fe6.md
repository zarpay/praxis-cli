The top-level describe block in a test file must name the unit under test by its module name, not by a vague label, feature name, or informal description. This enables readers to immediately identify what is being tested and maintains consistency across the test suite.

## Violating example

describe('awards', ...) when testing the pickWinners module

## Compliant example

describe('pickWinners', ...) when testing the pickWinners module
