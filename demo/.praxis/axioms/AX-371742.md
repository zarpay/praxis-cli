Test suites must use nested describe blocks to frame different situations or scenarios, with each nested describe naming the situation in a way that clearly communicates the context being tested. This organizes tests by meaningful context and enables readable test structure.

## Violating example

describe('send-newsletter', () => {
  it('works', () => { ... })
}) // No nested describes for different scenarios

## Compliant example

describe('send-newsletter', () => {
  describe('when subject is valid', () => {
    it('returns true', () => { ... })
  })
  describe('when subject is empty', () => {
    it('throws an error', () => { ... })
  })
})
