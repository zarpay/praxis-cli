The top-level describe block in a test file must name the unit under test by its module name (e.g., 'send-newsletter', 'create-review'), not by feature folder names, informal labels, or vague descriptions. This naming convention ensures tests clearly identify what specific module is being tested and maintains consistency across the test suite.

## Violating example

describe('newsletter stuff', ...) or describe('awards', ...) when testing a module named send-newsletter or pickWinners

## Compliant example

describe('send-newsletter', ...) when testing the send-newsletter module, or describe('pickWinners', ...) when testing the pickWinners module
